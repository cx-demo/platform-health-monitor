# PHMS architecture

## Purpose

The Platform Health & Mission Readiness Service (PHMS) exposes subsystem
telemetry for a mixed fleet through a single sustainment API. Maintenance
planning, sortie generation, availability reporting and the customer
sustainment portal all consume it.

## Layering

| Layer | Module | Responsibility |
|---|---|---|
| Transport | `src/main.py` | FastAPI routes, HTTP status codes, error shaping. No business rules. |
| Domain | `src/readiness_service.py` | Projection of the internal platform model onto the ICD payload. All classification logic belongs here. |
| Model | `src/models.py` | Pydantic v2 internal domain model. |
| Data | `src/repository.py` | Platform store. In-memory fixture in this build; a sustainment data source in production. |

The layering is enforced by review and by `.github/copilot-instructions.md`.
Route handlers must not contain business rules.

## Internal model vs. public payload

`src/models.py` carries more information than the API exposes. `mission_critical_fault`
and `telemetry_age_seconds` are internal diagnostics and are deliberately **not**
projected by `get_platform_summary`. Leaking fault codes or diagnostic detail
through the public API is a security and interface concern, not a convenience.

The projection function is the single point at which internal state becomes
external contract. Any change there is an ICD-PHM-002 interface change.

## Interface control

`docs/icd/ICD-PHM-002.md` is the controlling document for the public payload.
`tests/contract/test_icd_phm_002_compatibility.py` asserts the declared field
set exactly — additional undeclared fields fail the contract suite, because at
least one downstream consumer validates strictly.

The OpenAPI document generated by FastAPI at `/openapi.json` is the
machine-readable form of the ICD and is expected to agree with it.

## Fleet fixture

Three platforms, one per customer domain:

| Platform | Type | Domain reading |
|---|---|---|
| `LND-114` | `LAND` | Vehicle serviceability, powerpack/drivetrain health |
| `AIR-207` | `AIR` | Subsystem prognostics feeding dispatch decisions |
| `MSN-330` | `MISSION_SYSTEM` | Deployed mission system readiness rollup |

`MSN-330` deliberately carries a mission-critical fault, a 94 °C generator and a
stale comms telemetry age. None of that is visible through the current API —
which is precisely the problem SYS-4412 addresses.
